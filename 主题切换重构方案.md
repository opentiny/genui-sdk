# 主题切换重构方案

## 一、背景与问题

### 1.1 现状

GenUI SDK 是一个**多 UI 库适配**的低代码渲染框架，其核心架构分为三层：

| 层级 | 包 | 职责 |
|------|----|------|
| **Core 层** | `@opentiny/genui-sdk-core` | 定义协议、类型、纯逻辑工具，不依赖任何具体 UI 库 |
| **应用层** | `@opentiny/genui-sdk-vue` | Vue 框架适配（ConfigProvider / Chat 等），编排材料 |
| **Materials 层** | `vue-opentiny-vue` / `vue-element-plus` | 各 UI 库的组件、主题、元数据等具体实现 |

主题切换的能力，此前全部**硬编码在 应用层的 `ConfigProvider.vue` 中**，直接 import 了 OpenTiny Vue 的三件套：

```ts
// 重构前 —— 应用层与 OpenTiny Vue 强耦合
import { TinyConfigProvider } from '@opentiny/vue';
import ThemeTool, { tinyDarkTheme, tinyOldTheme } from '@opentiny/vue-theme/theme-tool';
```

### 1.2 痛点

1. **架构耦合**：应用层本应只做"编排"，现在却绑定了 OpenTiny Vue 的主题实现。Element Plus 材料包、未来可能的 Ant Design / Naive UI 材料包，都无法复用这套主题机制。
2. **无法多主题共存**：当宿主同时引入两套材料（如 OpenTiny + Element Plus 混用）时，主题无法分别应用。
3. **扩展受限**：新增一个主题（如"清新 lite"）必须改 应用层代码，违反开闭原则。
4. **语义模糊**：原 `theme` 字段同时承载"主题 id"（light/dark/lite）与"颜色模式"（light/dark）两种语义，下游消费方（Chat、Footer、Monaco 等）各自做 `=== 'dark'` 判断，重复且易错。

---

## 二、方案目标

1. **主题能力下沉**：把"如何切换主题"的具体实现从 应用层移到 Materials 层，每个材料包自己负责。
2. **Core 层只定协议**：在 Core 层定义通用接口 `IMaterialsTheme`，不依赖任何 UI 库。
3. **应用层只做编排**：ConfigProvider 退化为"调度器"，遍历材料包提供的主题实现并调用，不关心具体细节。
4. **支持多材料主题共存**：通过 `mergeMaterials` 合并多套材料时，主题实现可叠加。
5. **语义分层**：区分"主题 id"（用户选了哪个主题）与"颜色模式 colorScheme"（最终是亮还是暗），下游统一消费 `colorScheme`。

---

## 三、核心原则

本方案遵循三层职责分离原则，每层只做自己该做的事：

| 层 | 职责 | 核心动作 | 不做什么 |
|----|------|----------|----------|
| **Core 包** | 定义协议 | 声明 `IMaterialsTheme` 接口、`ThemeApplyContext`、`ThemeDisposer` 等类型 | 不实现任何主题切换逻辑，不依赖任何 UI 库 |
| **Materials 包** | 实现主题 | 每个材料包通过 `createMaterialsTheme()` 实现 `IMaterialsTheme`，决定自己"怎么切" | 不关心谁来调用自己，不关心 ConfigProvider 的存在 |
| **ConfigProvider（应用层）** | 实际调用 | 收集所有材料主题 → 逐个调用 `apply()` → 渲染它们声明的 `Root` 组件 | 不 import 任何 UI 库主题包，不关心主题具体怎么切 |

> **一句话总结**：Core 定契约，Materials 做实现，ConfigProvider 做调度。

```
┌──────────────────────────────────────────────────────────────┐
│  Core 包                                                     │
│  ─ 定义 IMaterialsTheme 协议                                 │
│  ─ 提供 mergeMaterials 合并工具                              │
└────────────────────────────┬─────────────────────────────────┘
                             │ implements
                             │
┌────────────────────────────┼─────────────────────────────────┐
│  Materials 包            │                                   │
│  ┌─────────────────────────────────┐  ┌────────────────────┐│
│  │ vue-opentiny-vue                │  │ vue-element-plus   ││
│  │ createMaterialsTheme()          │  │ createMaterialsTheme()│
│  │  └─ apply: ThemeTool 注入 CSS  │  │  └─ apply: .dark class│
│  └─────────────────────────────────┘  └────────────────────┘│
└────────────────────────────┬─────────────────────────────────┘
                             │ apply()
                             │
┌────────────────────────────┼─────────────────────────────────┐
│  ConfigProvider（应用层） │                                   │
│  ─ 收集所有 materials.theme                                  │
│  ─ watch 变化 → clearTheme() → 逐个 apply()                │
│  ─ 渲染各材料的 Root 组件                                   │
│  ─ 注入 colorScheme 给下游                                  │
└──────────────────────────────────────────────────────────────┘
```

## 四、总体设计

### 4.1 核心思路：依赖反转 + 策略模式

> **把"切换主题"这件事从"ConfigProvider 知道怎么做"变成"材料包告诉 ConfigProvider 怎么做"。**

ConfigProvider 不再 import 任何 UI 库的主题工具，而是通过 `IMaterialsTheme` 接口，让每个材料包自己实现 `apply()`。ConfigProvider 只负责：**收集所有材料主题 → 逐个调用 apply → 渲染它们声明的 Root 组件**。

### 4.2 分层职责（重构后）

```
┌─────────────────────────────────────────────────────────┐
│  Core 层 (genui-sdk-core)                               │
│  ─ 定义协议：IMaterialsTheme / ThemeApplyContext        │
│  ─ 合并工具：mergeMaterials?                             │
│                                                         │
├─────────────────────────────────────────────────────────┤
│  应用层 (genui-sdk-vue)                           │
│  ─ ConfigProvider：编排，调用 apply()，渲染 Root         │
│  ─ 注入 colorScheme 给下游                              │
│  ─ 不 import 任何 UI 库主题包                           │
├─────────────────────────────────────────────────────────┤
│  Materials 层                                            │
│  ─ vue-opentiny-vue：createMaterialsTheme()     │
│      ├─ 用 ThemeTool + tinyDarkTheme/lite 切 CSS         │
│      └─ Root = OpenTinyThemeRoot (TinyConfigProvider)   │
│  ─ vue-element-plus：createMaterialsTheme()  │
│      └─ 用 .dark class 切换                              │
└─────────────────────────────────────────────────────────┘
```

## 五、详细设计

### 5.1 Core 层：主题协议定义

在 `packages/core/src/material/materials-theme.ts` 新增四个类型，构成整个方案的"契约"：

```ts
// 颜色模式：只有亮/暗两种，是下游唯一需要关心的语义
export type ThemeColorScheme = 'light' | 'dark';

// 主题描述：一个主题的元信息（id、显示名、所属颜色模式）
export interface ThemeDescriptor {
  id: string;            // 'light' | 'dark' | 'lite' | ...
  label?: string;        // '浅色' | '深色' | '清新'
  colorScheme?: ThemeColorScheme;
}

// apply 时传入的上下文
export interface ThemeApplyContext {
  scopeId: string;       // 作用域 id（ConfigProvider 的 id），用于 CSS 作用域隔离
  rootEl?: HTMLElement | null;  // 主题作用根节点
  systemColorScheme: ThemeColorScheme;  // 系统偏好（auto 时用）
}

// 卸载钩子：apply 返回的清理函数，用于切换/卸载时回滚
export type ThemeDisposer = () => void;

// ★ 核心接口：每个材料包实现它
export interface IMaterialsTheme {
  themes?: ThemeDescriptor[];                              // 该材料支持哪些主题
  apply(theme: string, ctx: ThemeApplyContext): void | ThemeDisposer;  // 应用主题
  Root?: unknown;                                          // 可选：需要包裹的根组件
}
```

**设计要点**：
- `apply` 返回 `ThemeDisposer`（可选），支持主题切换时清理上一主题的副作用（如移除 class、恢复 CSS）。
- `Root` 是可选的"主题根组件"——有些 UI 库（OpenTiny）必须用 `TinyConfigProvider` 包裹才能生效，Element Plus 则不需要。由材料包自己声明。
- `themes` 是声明式的主题清单，未来可用于主题选择器 UI。

### 5.2 Core 层：扩展 IMaterials

在 `materials.ts` 的 `IMaterials` 接口上新增 `theme` 字段：

```ts
export interface IMaterials {
  components?: IMaterialsMap;
  requiredCompleteFieldSelectors?: string[];
  defaultPropsMap?: Record<string, any>;
  theme?: IMaterialsTheme | IMaterialsTheme[];  // ★ 新增
  [key: string]: any;
}
```

支持单个或数组（为多材料共存预留）。

### 5.3 Core 层：mergeMaterials 合并工具

新增 `merge-materials.ts`，合并多套材料的 components / selectors / propsMap / theme：

```ts
const KNOWN_KEYS = ['components', 'requiredCompleteFieldSelectors', 'defaultPropsMap', 'theme'];

export function mergeMaterials(...sources: (IMaterials | undefined)[]): IMaterials {
  // components：Object.assign 浅合并（后者覆盖前者）
  // requiredCompleteFieldSelectors：去重 union
  // defaultPropsMap：Object.assign
  // theme：按引用去重收集成数组（保留所有材料主题，不互相覆盖）
  // 其余 extra key：后者覆盖
  // 最终 theme 字段：1 个则单值，>1 个则数组，0 个则不写

```

**theme 合并策略**：按对象引用去重（`Set<IMaterialsTheme>`），保证同一材料主题不会被重复收集；不同材料的主题保留为数组，由 ConfigProvider 逐个 apply。

### 5.4 Materials 层：OpenTiny Vue 主题实现

`vue-opentiny-vue/src/materials/theme/index.ts`：

```ts
export function createMaterialsTheme(): IMaterialsTheme {
  return {
    themes: [
      { id: 'light', label: '浅色', colorScheme: 'light' },
      { id: 'dark',  label: '深色', colorScheme: 'dark'  },
      { id: 'lite',  label: '清新', colorScheme: 'light' },  // OpenTiny 独有
    ],
    Root: OpenTinyThemeRoot,  // 必须用 TinyConfigProvider 包裹
    apply(theme, ctx): ThemeDisposer {
      // 1. 解析主题 id（不认识的主题回退到系统色）
      const themeId = resolveThemeId(theme, ctx.systemColorScheme);
      // 2. 构造主题配置：把 :host/:root 替换为 #scopeId 做作用域隔离
      const themeConfig = buildThemeConfig(themeId, ctx.scopeId);
      // 3. 调 ThemeTool 注入 CSS
      const themeTool = new ThemeTool();
      themeTool.changeTheme(themeConfig);
      // 4. 返回 disposer：恢复为空白主题
      return () => themeTool.changeTheme({ css: ' ' });
    },
  };
}
```

`ThemeRoot.ts`：把原来的 `TinyConfigProvider` 包裹逻辑封装成 `OpenTinyThemeRoot` 组件，挂载时移除默认 class。

### 5.5 Materials 层：Element Plus 主题实现

`vue-element-plus/src/materials/theme/index.ts`：

```ts
export function createMaterialsTheme(): IMaterialsTheme {
  return {
    themes: [
      { id: 'light', label: '浅色', colorScheme: 'light' },
      { id: 'dark',  label: '深色', colorScheme: 'dark'  },
    ],
    // 无 Root：Element Plus 用 html.dark class，不需要根组件包裹
    apply(theme, ctx): ThemeDisposer {
      const el = document.getElementById(ctx.scopeId);
      if (resolveColorScheme(theme, ctx.systemColorScheme) === 'dark') {
        el?.classList.add('dark');
      } else {
        el?.classList.remove('dark');
      }
      return () => el?.classList.remove('dark');
    },
  };
}
```

**对比可见**：两套材料的 `apply` 实现完全不同（一个注入 CSS、一个切 class），但对外接口一致——这就是协议的价值。

### 5.6 应用层：ConfigProvider 编排

ConfigProvider 重构为纯调度器，核心逻辑三段：

**(1) 收集材料主题**

```ts
const materialThemes = computed<IMaterialsTheme[]>(() => {
  const t = props.materials?.theme;
  return t ? (Array.isArray(t) ? t : [t]) : [];
});
```

**(2) 解析颜色模式并注入下游**

```ts
const theme = computed(() => props.theme || 'light');           // 用户选的主题 id
const colorScheme = computed<ThemeColorScheme>(() =>            // 最终颜色模式
  theme.value === 'auto' ? mediaTheme.value
                         : (theme.value === 'dark' ? 'dark' : 'light')
);
provide(GENUI_CONFIG, computed(() => ({ colorScheme, id: props.id })));
```

下游（Chat / Footer / Monaco）统一读 `colorScheme`，不再各自判断 `theme === 'dark'`。

**(3) 调用 apply + 渲染 Root**

```ts
let disposers: ThemeDisposer[] = [];

watch(
  () => [materialThemes.value, theme.value, mediaTheme.value, props.id, rootRef.value],
  ([apis, themeValue, systemColorScheme, scopeId, root]) => {
    clearTheme();                          // 先清理上一轮 disposer
    const rootEl = resolveRootEl(root);
    for (const api of apis) {
      const dispose = api.apply(themeValue, { scopeId, rootEl, systemColorScheme });
      if (dispose) disposers.push(dispose);
    }
  },
  { immediate: true },
);
onBeforeUnmount(clearTheme);
```

模板里用 `ThemeRoots` 把各材料声明的 `Root` 组件**从外到内嵌套**包裹 slot：

```vue
<ThemeProvider v-bind="robotProviderProps">
  <ThemeRoots :roots="themeRoots">
    <slot />
  </ThemeRoots>
</ThemeProvider>
```

`ThemeRoots` 用 `reduceRight` 把多个 Root 组件层层包裹（`[A, B]` → `<A><B><slot/></B></A>`）。

## 七、对下游的影响与适配

原 `GENUI_CONFIG` 注入的是 `{ theme, id }`，下游用 `config.theme === 'dark'` 判断。重构后改为 `{ colorScheme, id }`，下游统一改为读 `colorScheme`：

| 文件 | 改动 |
|------|------|
| `GenuiChat.vue` | `genuiConfig?.theme` → `genuiConfig?.colorScheme` |
| `AssistantFooter.vue` / `UserFooter.vue` | tooltip 判断改读 `colorScheme` |
| `GenuiTemplateChat.vue` | watch 改 `colorScheme`，`setColorMode` 直接传 |
| `use-monaco-playground-theme.ts` | 读 `colorScheme` 决定 `vs` / `vs-dark` |
| `injection-tokens.ts` | `GENUI_CONFIG` 类型收紧为 `ComputedRef<GenuiConfigState>` |

**语义收益**：下游不再需要理解"主题 id 可能是 lite/auto"，只需关心最终的亮/暗。

## 八、扩展性验证

### 场景 1：新增第三套材料（如 Ant Design Vue）

只需在材料包内实现 `IMaterialsTheme`，无需改 Core / 应用层：

```ts
// vue-antd-vue/src/materials/theme/index.ts
export function createAntdMaterialsTheme(): IMaterialsTheme {
  return {
    themes: [{ id: 'light', colorScheme: 'light' }, { id: 'dark', colorScheme: 'dark' }],
    Root: AntdConfigProvider,  // antd 需要 ConfigProvider 包裹
    apply(theme, ctx) {
      // antd 的主题切换实现...
      return () => { /* 回滚 */ };
    },
  };
}
```

### 场景 2：多材料混用

宿主同时用 OpenTiny + Element Plus：

```ts
const materials = mergeMaterials(openTinyMaterials, elementPlusMaterials);
// materials.theme = [openTinyTheme, elementPlusTheme]
```

ConfigProvider 会**两个都 apply**，两套主题 CSS/class 同时生效；`ThemeRoots` 会把 `OpenTinyThemeRoot` 包在外层。

### 场景 3：新增主题选项（如"高对比度"）

只改对应材料包的 `themes` 声明与 `apply` 分支，应用层零改动。

## 九、风险评估

| 风险 | 等级 | 说明 / 应对 |
|------|------|------------|
| 下游 `GENUI_CONFIG` 消费方需全量适配 | 低 | 已在本 commit 同步改造所有下游（Chat/Footer/Monaco/Template） |
| `mergeMaterials` theme 按引用去重 | 低 | 同一材料对象不会重复；不同材料实例视为不同主题，符合预期 |
| `ThemeTool` 每次 apply 都 new | 低 | OpenTiny 材料包内 `new ThemeTool()` 在 apply 内，频率可控；如需优化可提到工厂闭包外 |
| `Root` 嵌套顺序 | 低 | `reduceRight` 保证声明顺序即嵌套顺序，可预期 |
| auto 主题响应系统偏好 | 已覆盖 | `useMediaTheme` 监听 `prefers-color-scheme`，变化触发 watch 重 apply |

## 十、总结

本次重构的核心是**依赖反转**：把"主题怎么切"的知识从 应用层下放到 Materials 层，Core 层只定协议。收益：

1. **应用层解耦**：不再 import 任何 UI 库主题包，回归"纯编排"定位。
2. **材料自治**：每套 UI 库的主题实现内聚在各自材料包，符合开闭原则。
3. **多材料可共存**：`mergeMaterials` + 数组 theme + `ThemeRoots` 嵌套，支持混用。
4. **语义清晰**：`colorScheme` 与 `theme id` 分层，下游消费统一。
5. **可扩展**：新增 UI 库 / 新主题选项，应用层与 Core 零改动。

请领导评审方案的架构方向与接口设计是否认可，通过后即可推进剩余材料包（如未来 Angular / 其他 Vue 库）的主题适配。
