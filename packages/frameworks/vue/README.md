# @opentiny/genui-sdk-vue

A Vue 3 component library for enhanced LLM display and interaction. Stream AI-generated structured output into OpenTiny interactive UI components with bidirectional conversation support.

- **Streaming Rendering:** Content renders progressively as the model generates—no long waits for full responses.
- **Structured Output:** LLM output conforms to JSON Schema, enabling reliable parsing and rendering.
- **Interaction:** User actions (form submit, button click) feed back into the conversation context for seamless multi-turn flows.

[Learn more about GenUI SDK](https://opentiny.design/genui-sdk).

## Usage

Install together with core and the Vue materials package (the renderer is bundled in the vue package):

```bash
pnpm add @opentiny/genui-sdk-vue @opentiny/genui-sdk-core @opentiny/genui-sdk-materials-vue-opentiny-vue
```

```vue
<script setup>
import { GenuiChat, GenuiConfigProvider } from '@opentiny/genui-sdk-vue';
import { materials } from '@opentiny/genui-sdk-materials-vue-opentiny-vue/materials';
</script>

<template>
  <GenuiConfigProvider theme="dark" :materials="materials">
    <GenuiChat url="/api/chat" model="deepseek-chat" />
  </GenuiConfigProvider>
</template>
```

Import by feature via subpaths (`/chat`, `/renderer`, `/config-provider`, `/code-generator`) to avoid unused modules:

```ts
import { generateCode } from '@opentiny/genui-sdk-vue/code-generator';
```

## Web Component

### Bundled renderer (OpenTiny Vue materials)

`@opentiny/genui-sdk-vue` ships a ready-to-use custom element with the OpenTiny Vue materials already bundled. It is a single self-contained ES module, and one tag does everything — rendering, theme and i18n:

```html
<script
  type="module"
  src="https://unpkg.com/@opentiny/genui-sdk-vue/dist/web-component/genui-config-renderer.js"
></script>
<genui-config-renderer
  content='{"componentName":"Page","children":[{"componentName":"TinyButton","props":{"text":"Hello"}}]}'
></genui-config-renderer>
```

When you bundle it yourself, import it from the package instead of copying the file:

```ts
import '@opentiny/genui-sdk-vue/web-component'; // registers <genui-config-renderer>
```

The bundle auto-registers the `<genui-config-renderer>` tag and exports `GenuiConfigRendererElement`, `GENUI_CONFIG_RENDERER_TAG`, `registerGenuiConfigRenderer`, `materials` and `materialKey`. `./web-component-factory` exports `createGenuiConfigRendererElement(materials)` if you want to wire the custom element into your own bundle.

### Theme and locale

`theme` and `locale` are attributes on the element itself — there is nothing to wrap:

```html
<genui-config-renderer theme="dark" locale="zh_CN" content='{"componentName":"Page","children":[]}'></genui-config-renderer>
```

```js
document.querySelector('genui-config-renderer').theme = 'auto'; // follows prefers-color-scheme
```

| Attribute           | Description                                                                                                                                           |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `theme`             | `light` \| `dark` \| `auto` (follows the system), default `light`                                                                                     |
| `locale`            | e.g. `zh_CN` \| `en_US`                                                                                                                               |
| `i18n`              | extra messages, JSON string or object                                                                                                                 |
| `id`                | Native id of the host element, also handed to the renderer as the card id. The inner container id is generated by the element and is unaffected by it |
| `content`           | The schema to render: JSON string as an attribute, object as a property                                                                               |
| `generating`        | Streaming in progress                                                                                                                                 |
| `custom-components` | Extra components merged into the materials, JSON string or object                                                                                     |
| `state`             | Initial state, JSON string or object                                                                                                                  |

Materials always come from the build — the element has no `materials` property to override them at runtime.

The materials' `themeFactory` wraps the content in a scoped theme root and injects the theme CSS; `theme` is isolated per element.

`locale` is **not** isolated — i18n is a module-level singleton shared by the whole bundle. Every element's internal config provider pushes its own `locale` into it, so an element without an explicit `locale` falls back to the default `zh_CN` and writes that back globally, affecting elements created afterwards. Always set `locale` explicitly. Messages are also resolved when the element is created, so re-create the element after changing `locale`.

### Build a renderer with your own materials

The package also publishes a CLI, `genui-build-web-component`, which bundles the renderer together with any Vue materials library you point it at.

```bash
# npm package (defaults to the package's /materials entry)
npx genui-build-web-component --materials @scope/my-materials

# local path: a file, or a directory with package.json / dist/materials.js / src/index.ts
npx genui-build-web-component --materials ./my-materials --tag my-genui --out-dir dist/web-component
```

| Option                         | Description                                                                                                 |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `-m, --materials <source>`     | npm package name or local path. Repeatable (or comma separated); several sources are merged into one bundle |
| `-t, --tag <name>`             | Tag the bundle auto-registers (default `genui-config-renderer`)                                               |
| `-o, --out-dir <dir>`          | Output directory (default `dist/web-component`)                                                             |
| `-f, --file-name <name>`       | Output file name without extension (default `genui-config-renderer`)                                          |
| `--no-minify` / `--sourcemap`  | Disable minification / emit a source map                                                                    |
| `-h, --help` / `-v, --version` | Help / version                                                                                              |

Output is `<out-dir>/<file-name>.js` plus a matching `.d.ts`:

```ts
import '@scope/my-materials-built/genui-config-renderer'; // or <script type="module" src="genui-config-renderer.js">
```

A materials module only has to export `materials`, the same shape the in-repo materials packages use:

```ts
// my-materials/materials.ts
import type { IMaterials } from '@opentiny/genui-sdk-core';
import MyBadge from './MyBadge.vue';

export const materials: IMaterials = { components: { MyBadge }, actions: {} };
```

```json
//my-materials/package.json
{
  "name": "my-materials",
  "exports": {
    "./materials": "./materials.ts"
  }
}
```

### Building the in-repo bundle

This repository builds exactly one Web Component bundle — the OpenTiny Vue one that ships with the package:

```bash
pnpm build:web-component   # -> dist/web-component/genui-config-renderer.js + genui-config-renderer.d.ts
```

Other materials (Element Plus, in-house component libraries, …) are intentionally **not** built here; users build them with the CLI described above, which keeps this repository free of third-party material dependencies.

> `vite`, `@vitejs/plugin-vue` and `vite-plugin-css-injected-by-js` are regular dependencies so the CLI works without extra setup. If install size matters more than zero-config, they can be moved to optional `peerDependencies` plus a CLI preflight check.

For a step-by-step walkthrough of both build paths (what runs, what gets resolved, what the output looks like), see [docs/web-component-build.md](./docs/web-component-build.md) (Chinese).
